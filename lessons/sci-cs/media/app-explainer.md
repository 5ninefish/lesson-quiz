- A tap as an event that runs one instruction, "go to the screen you chose". The person supplies the tap and the computer runs the program.
- The page's reference app, screen by screen.
- The editor flow, step by step:
  - Editing screen 1. An empty preview shows "Untitled screen" and "This screen has no explanation yet."
  - Typing a title and body, with the preview updating as you type.
  - Labeling Button A and choosing where it goes. Button A starts at 1.
  - Changing Editing screen, which shows that screen's own words and moves the preview.
  - Filling screens 2 and 3.
  - The optional Button B as a way back. Its "goes to" starts blank.
- Walking the preview, and the "Preview is showing screen N." line.
- No hidden Next order.
- The page's bug and repair: Button A on screen 2 pointing at 2, then at 3.
- Reset the walk, which clears the walk and sends the preview back to screen 1. Then the walk is done again.
- The "One connection or repair" box, a pause-and-think beat, and Check the app.

No sample sentence is given. Every screen's text is the page's reference app. The editor and preview are drawn to match the page's fields and lesson_client.js behaviour. Narration voice: Kokoro (af_heart). Sound effects are synthesized.

## Narration

This is App. The goal: three screens you can walk, including a way back.
An app can be a few screens, connected by buttons.
A button press is an event. It runs one instruction: go to the screen you chose.
The person supplies the tap. The computer runs the program.
Here's the reference app. Screen 1: What is lauhala? Button A, How to coil, goes to screen 2.
Screen 2: How the rose is made. Button A, See the rose, goes to screen 3. Button B, Back, goes to screen 1.
Screen 3: Finished rose. Button A, Start over, goes to screen 1.
Now, the editor. Leave Editing screen on 1.
Before you type, the preview says Untitled screen, and This screen has no explanation yet.
Type a title, and a short explanation. The preview updates as you type.
Next, label Button A, and choose where it goes. Here, How to coil goes to screen 2.
Button A starts out pointing at screen 1, so check where it goes on every screen.
Now change Editing screen to 2. The boxes show that screen's own words, and the preview moves to screen 2.
Fill in screen 2 the same way, then screen 3.
Button B is optional. Use it for a way back. On screen 2, Back goes to screen 1.
Copying the reference app is allowed.
Now walk it. Tap the buttons in the preview: screen 1, screen 2, screen 3, then back to screen 1.
The line under the preview tells you where you are.
The preview uses your destinations. There's no hidden Next order.
So if Button A on screen 2 points at screen 2, the preview stays put.
That's a bug. To repair it, point Button A at screen 3.
Then press Reset the walk. It clears the walk, and the preview goes back to screen 1.
Walk it again: 1, 2, 3, and back to 1.
Last, write one sentence about a connection, or a repair. Make the sentence yours.
Now you try. Which connection, or which repair, will you write about? Pause, and write it in your own words.
Then press Check the app.
